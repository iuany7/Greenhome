# 首页与核心交互优化

## 本轮变更

- 首页按连接状态、环境概览、设备控制、阈值设置和工具入口组织，使用浅绿背景和白色圆角卡片。
- 首次进入显示空值，保留最近数据更新时间；不再把布局示例值当作实时数据。
- 使用已配置的 MQTT 连接选项，先初始化 Handler 再启动连接，串行执行重连和发送，避免在主线程等待网络。
- 离线禁用控制；设备状态由硬件上报驱动，程序同步开关不发送命令。手动模式不再重置设备开关。
- 完整校验传感器帧后再更新和保存，异常数据保留原读数；销毁页面时停止重连并清理连接。
- 功能入口增加文字；原仓库缺少 dashboard.html，数据看板入口暂时显示明确说明。图像识别入口标注演示。

## 尚需 Android 环境验证

本机没有 Android SDK，不能据此宣称 APK 编译或真机测试通过。静态检查不能替代以下验收：

1. Android Studio 使用 JDK 17 和 Android SDK 33，运行 assembleDebug、lintDebug。
2. 在 320dp、常规手机宽度和大字体下检查首页滚动、数据卡片、按钮及夜间系统设置下的可读性。
3. 使用隔离的测试 MQTT broker 和测试设备：验证凭据连接、首次订阅、断网重连和 Activity 退出后的连接清理。
4. 发布 sensor1–sensor10 为数字、sensor11–sensor15 为 0/1 的完整 JSON：确认数据及开关更新且没有额外控制消息。
5. 发布缺字段、非数字、NaN、非法设备状态：不得崩溃或覆盖原记录。
6. 切换手动模式不得发出五个 OFF 指令；开关点击只发送对应指令，实际状态等待设备回报。验证发送失败提示。
7. 验证阈值加减及模式指令与现有固件兼容；模式与阈值开关目前表示用户请求，协议未提供其确认字段。

## 已知边界

- 使用原有 MQTT QoS 0，发送成功不等于硬件执行成功；界面已明确提示以回报为准。
- 本轮未更改服务器、认证配置或 AI 接口；未实现图像识别后端或缺失的数据看板。
- 最近更新时间为本机收到数据的时间，不能代表硬件采样时间。
